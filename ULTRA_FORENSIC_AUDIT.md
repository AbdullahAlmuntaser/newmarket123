## 2. Phase 1-4: Forensic Logic & Integrity Audit

### 🔴 Critical Architectural Violation: Atomic Integrity Failure
**Finding:** The system decouples Inventory Updates (`TransactionEngine`) from General Ledger Posting (`AccountingService`) via an asynchronous `EventBus`.
**Risk:** High. If the `EventBus` fails or the app crashes between the two transactions, the system state will be corrupted (e.g., stock decreased but no GL entry created). 
**Recommendation:** Move `postSale` logic into a single atomic database transaction encompassing both stock movement and GL entry creation.

### 🔴 Memory & Performance Bottleneck: In-Memory Stream Pagination
**Finding:** `ProductsPage.dart` watches the *entire* products table (`watchProducts`) and performs pagination/sub-listing in Dart memory.
**Risk:** Severe. As inventory grows (10k+ items), this will cause OOM (Out of Memory) crashes and UI freezes during search/scroll.
**Recommendation:** Implement server-side/DAO-level pagination using `limit` and `offset` in SQL queries.

### 🟡 Database Maintenance Risk: Regex-based Migrations
**Finding:** `convert_to_encrypted.dart` uses regex patterns to modify `CREATE INDEX` statements.
**Risk:** Moderate. Brittle migration logic could fail if SQL syntax changes or if complex indexes are added.
**Recommendation:** Use Drift's built-in migration API instead of raw string manipulation.

## 3. Phase 5-7: Security & Runtime Forensics

### 🔴 Security Risk: SQLCipher Fallback Mechanism
**Finding:** `native_sql_override.dart` attempts to load `libsqlcipher.so` but falls back to `libsqlite3.so` or `DynamicLibrary.process()` if it fails.
**Risk:** High. In a production build, if the encrypted library fails to load, the system might accidentally open or create an unencrypted database, exposing sensitive financial data.
**Recommendation:** Remove fallbacks in release builds. Fail fast if encryption cannot be guaranteed.

### 🟡 Resource Leakage: Unguarded Logs
**Finding:** 65 instances of `debugPrint` found without `kDebugMode` wrappers.
**Risk:** Low-Medium. Potential leakage of internal system state or PII into device logcat in production.
**Recommendation:** Wrap all debug logs in `if (kDebugMode)` or use a dedicated logging service that respects build modes.

### 🔴 Sync Integrity Gap: Disconnected SyncQueue
**Finding:** `SyncQueue` exists in the schema, but core DAOs (Sales, Purchases) do not insert mutation logs into it.
**Risk:** Severe. Offline functionality is a "mirage"; data will not sync correctly because mutations aren't being tracked at the source.
**Recommendation:** Implement a trigger or automated logic in DAOs to log all `create/update/delete` operations into `SyncQueue`.
